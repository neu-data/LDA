# Module 2 cheat sheet input: Preparing and exploring longitudinal data

## Reshaping between long and wide (tidyr)

- **Purpose:** move between one row per observation (long, needed for models and plots) and one row per participant (wide, for some summaries, visit correlations and imputation).
- **Key assumptions:** the participant–visit key is unique; column names encode time consistently; wide format holds scheduled time only.
- **R example:**
  ```r
  long <- wide |>
    pivot_longer(starts_with("sbp_m"), names_to = "month_sched",
                 names_prefix = "sbp_m",
                 names_transform = list(month_sched = as.numeric),
                 values_to = "sbp")
  wide2 <- long |> select(id, arm, month_sched, sbp) |>
    pivot_wider(names_from = month_sched, values_from = sbp, names_prefix = "sbp_m")
  ```
- **Report:** rows before and after; number of `NA` (missed visits); round-trip check.
- **Common error:** leaving a time-varying column (actual time, steps) in `pivot_wider()`, which gives one row per visit.

## Joining participant-level and visit-level files

- **Purpose:** put baseline covariates, arm and randomisation date on every visit row.
- **Key assumptions:** identical key spelling and type in both files; one row per participant in the participant-level file.
- **R example:**
  ```r
  joined <- visits |>
    left_join(baseline |> select(id, rand_date, sbp0),
              by = "id", relationship = "many-to-one")
  stopifnot(nrow(joined) == nrow(visits))
  anti_join(visits, baseline, by = "id")   # unmatched visit records
  ```
- **Report:** rows before and after; unmatched keys in both directions.
- **Common error:** joining without `relationship =`, so a duplicated baseline row silently duplicates all of that participant's visits.

## Cleaning a raw visit export

- **Purpose:** produce one checked row per participant and visit, with actual time and flags, from a messy export.
- **Key assumptions:** rules for duplicates, implausible values and windows are fixed in advance (before unblinding) and do not depend on arm or outcome.
- **R example:**
  ```r
  raw <- read_csv(f, col_types = cols(.default = col_character()))
  d <- raw |> mutate(id = toupper(trimws(participant)),
                     visit_date = as.Date(visit_date, "%Y-%m-%d"),
                     sbp = parse_double(sbp_mmhg)) |> distinct()
  d |> add_count(id, visit) |> filter(n > 1)          # conflicting duplicates
  d <- d |> mutate(month = as.numeric(visit_date - rand_date) / 30.44)
  ```
- **Report:** a cleaning log (counts at each step) and a query log (one row per questioned value and the action taken).
- **Common error:** looking for duplicates before standardising IDs, so copies that differ only in case are missed.

## Missing-visit grid, summaries and participant flow

- **Purpose:** count missed visits (intermittent vs after dropout), describe the arms at baseline and the outcome at each visit, and report attendance.
- **Key assumptions:** the grid is built from the randomisation list and the protocol schedule, not from observed data; percentages use the randomised number.
- **R example:**
  ```r
  grid <- baseline |> select(id, arm) |> crossing(visit = 1:6) |>
    left_join(walk |> select(id, visit, sbp), by = c("id", "visit")) |>
    mutate(observed = !is.na(sbp))
  visit_flow(walk, id, month_sched, arm)
  ```
- **Report:** n (% of randomised) at each visit by arm; number of intermittent and post-dropout missing visits; baseline mean (SD) or n (%) by arm.
- **Common error:** testing baseline differences between randomised arms.

## Exploratory plots

- **Purpose:** see individual variation, the shape of change, missingness and dropout patterns before modelling.
- **Key assumptions:** plots of observed data describe those measured; subsets are random with a fixed seed.
- **R example:**
  ```r
  plot_spaghetti(walk, month, sbp, id, group = arm, n_show = 30, seed = 2)
  plot_observed_means(walk, month_sched, sbp, arm)
  plot_missing_map(grid, id, visit, observed, order_by = last_seen)
  ```
- **Report:** a sentence per plot: level vs slope variation, shape of change, type of missingness, whether dropouts differed before leaving.
- **Common error:** hand-picking "interesting" participants, or plotting individual trajectories against scheduled instead of actual time.

## Observed means versus model-estimated means

- **Purpose:** recognise that observed visit means estimate E(Y | observed), not E(Y), when dropout depends on the outcome history.
- **Key assumptions:** a mixed model fitted to all observed data is valid under MAR and correct model specification.
- **R example:**
  ```r
  m <- lmer(sbp ~ visit_f * arm + (1 + month | id), data = walk, control = lmer_ctrl)
  emmeans(m, ~ visit_f | arm)      # compare with observed means by visit
  ```
- **Report:** observed means with n (descriptive); model-based means and contrasts for inference.
- **Common error:** presenting observed visit means (or completers-only means) as the estimated treatment trajectory.

## Decision points (for method-selection diagrams)

- Does the analysis need one row per observation (models, plots)? Use long format. One row per participant (visit correlations, some imputation)? Use wide format.
- Do two records share a participant and visit? Identical in all fields after standardising: remove. Different: query; if unresolved, apply the prespecified rule and flag.
- Is a value outside the prespecified plausible range? Set to missing, keep the raw value, raise a query. Correct it only if the plan allows documented corrections.
- Is a visit outside its window? Keep it, flag it, and use actual time in the model; consider a sensitivity analysis.
- Does dropout appear related to earlier outcome values (pattern plots, last-value comparison)? Do not use observed visit means as estimates; use a likelihood-based model of all observed data (MAR) and plan sensitivity analyses (Module 10).
