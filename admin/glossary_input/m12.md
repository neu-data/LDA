# Module 12 glossary input

- **Follow-up schedule:** the planned times of the measurement occasions and the length of follow-up.
- **Front-loading:** placing more measurement occasions early in follow-up, where change is expected to be fastest.
- **Visit window:** the range of actual times that is accepted for a scheduled visit.
- **S_tt (spread of measurement times):** the sum of squared deviations of the measurement times from their mean; the larger it is, the more precisely an individual slope is estimated.
- **Planning values:** the assumed effect size and variance parameters used in a sample-size or power calculation.
- **Power:** the probability that the planned analysis rejects the null hypothesis when a specified alternative is true.
- **Simulation-based power:** power estimated as the proportion of simulated trials, generated from a planning model and analysed with the planned method, in which the null hypothesis is rejected.
- **Monte Carlo standard error (MCSE):** the standard error of a quantity estimated by simulation that is due to the finite number of simulated datasets; for a power estimate p from n_sims trials it is sqrt(p(1 - p) / n_sims).
- **Type I error:** rejecting a true null hypothesis; its rate should equal the nominal significance level.
- **Statistical analysis plan (SAP):** a dated, detailed description of the planned analyses, finalised before the data that bear on the main comparison are seen.
- **Estimand:** a precise description of the treatment effect to be estimated, defined in ICH E9(R1) by treatment conditions, population, variable, handling of intercurrent events and population-level summary.
- **Intercurrent event:** an event after randomisation (such as stopping treatment or taking rescue medication) that affects the existence or interpretation of the outcome; distinct from missing data.
- **Treatment-policy strategy:** handling an intercurrent event by using the outcome whether or not the event occurred.
- **Hypothetical strategy:** handling an intercurrent event by targeting the outcome that would have been observed had the event not occurred.
- **Composite strategy:** handling an intercurrent event by making its occurrence part of the outcome variable.
- **Sensitivity analysis:** an analysis that relaxes a specific assumption of the primary analysis to show how much the conclusion depends on it.
- **Reporting checklist:** a list of items (design, estimand, model, assumptions, missing data, results, reproducibility) that a complete report of a longitudinal analysis should contain.
- **Reproducibility:** the property that another analyst, given the data and code, obtains the same results.
- **R project:** a folder with an `.Rproj` file; opening it sets the working directory to the project root.
- **here():** a function from the here package that builds file paths relative to the project root.
- **sessionInfo():** an R function that reports the R version, platform and attached package versions.
- **renv:** an R package that gives a project its own package library and records package versions in a lockfile (`renv.lock`); `renv::init()`, `renv::snapshot()` and `renv::restore()` start, update and recreate the environment.
- **Version control (Git):** a system that records every change to files with a message, so that any earlier state can be recovered and the version that produced a result can be identified.
